# Java数据结构 数组&链表

在Java中，无论是List、Map、Stack还是Queue，它们底层最终都依赖于“数组（Array）”和“链表（Linked List/Node）”这两个最基础的物理存储结构，或者通过它们组合、演化而来。

- **为什么是这两种基础数据结构？**

> 从计算机底层（内存分配）角度来看，内存只有两种基本组织方式，分别是顺序存储和链式存储：
>
> 1.**顺序存储（数组）**：一块**连续**的内存；
>
> - 优点：查找快（连续的下标地址，可以直接推算）
> - 缺点：增删慢（在数组中间增减元素会导致之后的所有元素都移动）
>
> 2.**链式存储（链表）**：内存**分散**在各处,靠指针/引用连接；
>
> - 优点：增删快（任何一个元素的改动都不影响其他元素）
> - 缺点：查找慢（不是连续的地址，不能通过推算查找，必须从头遍历）

---
## 1.数组
在Java中，数组的概念很直观，可以直接创建一个数组，代码如下：
```java
public class Array {
    /**
     * 新建数组方式1：动态初始化
     * 只指定数组的长度，由系统自动为元素赋默认初始值（如整型为 0、浮点型为 0.0、引用类型为 null）
     */
    public void createArray1() {
        // 1.先声明，后创建
        int[] ints1;
        ints1 = new int[5]; // 创建长度为5的数组，每个元素默认为0

        Integer[] integers1;
        integers1 = new Integer[5]; // 创建长度为5的数组，每个元素默认为null

        // 2.声明和创建合并
        int[] ints2 = new int[5];
        Integer[] integers2 = new Integer[5];
    }

    /**
     * 新建数组方式2：静态初始化
     * 在创建数组时直接显式指定每个元素的初始值，由系统决定数组长度
     */
    public void createArray2() {
        // 1.完整语法
        int[] ints1 = new int[]{1, 2, 3, 4, 5};
        // 2.简写语法
        int[] int2 = {1, 2, 3, 4, 5};
    }
}

```

## 2.链表
在Java中，链表的概念并不像数组那么直观，链表在Java中的应用可以说是无处不在，任意Java对象都是对链表的直接使用。
- **怎么去理解链表？**

首先看链表的定义：**分散在各处的内存，靠指针/引用连接**；
   在Java中，我们新建任意一个对象**`User user = new User("张三");`**，`user`变量本质存储的是该对象在内存中的地址，也就是一个**引用**（直接打印`user`对象控制台会输出类名 + @ + 一串十六进制哈希码，注意：哈希码不等同于内存地址）；
```java
public class Link {
    public static void main(String[] args) {
        User user = new User("张三");
        System.out.println(user);
    }

    static class User {
        private String name;

        public User(String name) {
            this.name = name;
        }
    }
}
```
> 得到结果为：com.xielei.learn.p1_structure.structure.link.Link$User@2f4d3709

- **一个简单的链表**

链表分为单向和双向，根据链表中每个节点都持有另外一个节点的**引用**这个特点，我们来实现一个简单的双向链表，更直观感受一下链表在Java中的应用；
> 举个比较形象的例子，案件侦破过程中，往往需要对线索进行摸排，假设每一个线索都是通过上一个线索排查出来的，那么链表在Java中的表现如下：
```java
/**
 * <描述>: 双向链表，链表中的每个节点都持有前一个节点和后一个节点的引用
 */
public class DoubleLink {
    public static void main(String[] args) {
        // 假设有3条线索：A、B、C
        Clue A = new Clue("A");
        Clue B = new Clue("B");
        Clue C = new Clue("C");

        // 线索之间的联系是 A>B>C
        A.setAfter(B); // A线索之后是B线索

        B.setBefore(A); // B线索之前是A线索
        B.setAfter(C); // B线索之后是C线索

        C.setBefore(B); // C线索之前是B线索

        // 最开始我们只有线索A，我们如果需要找到线索C就需要从A开始排查，直到找到C线索
        Clue clue = A;
        while (clue != null) {
            System.out.println(clue.name);
            if ("C".equals(clue.name)) {
                System.out.println("找到了线索：" + clue.name);
                break;
            }
            clue = clue.after;
        }
    }

    /**
     * 线索对象
     */
    static class Clue {
        // 名字
        private String name;

        // 上一个线索
        private Clue before;

        // 下一个线索
        private Clue after;

        public Clue(String name) {
            this.name = name;
        }

        public void setBefore(Clue before) {
            this.before = before;
        }

        public void setAfter(Clue after) {
            this.after = after;
        }
    }
}
```
简单总结：从上面的两个例子中，可以得出一个结论，Java对象本身就是对链表这种数据结构的体现，如果链表是一串不连续的内存地址，那么**任意一个Java对象，就是只有一个元素的链表**。

## 3. 面试高频考点（补充）

### 3.1 数组和链表的复杂度对比

| 操作 | 数组（Array） | 链表（Linked List） |
| --- | --- | --- |
| 按下标随机访问 | **O(1)**（连续内存，地址可推算） | O(n)（必须从头遍历） |
| 头部插入/删除 | O(n)（需移动后面所有元素） | **O(1)**（只需改指针） |
| 尾部插入 | O(1)（容量充足时）；扩容时为 O(n) | O(1)（持有尾节点时） |
| 中间插入/删除 | O(n)（需移动元素） | O(n)（需先遍历到目标位置，但改指针为 O(1)） |
| 内存占用 | 连续，空间利用率高，但扩容有浪费 | 非连续，每个节点额外存储 next/prev 指针，内存开销大 |
| 缓存局部性 | **好**（连续内存，CPU 缓存友好） | 差（跳转访问，缓存命中率低） |

> **面试常问**：链表删除节点为什么是 O(1)？——前提是已经拿到该节点的引用（`node.pre = node.pre.pre` 之类），无需遍历；如果只知道值、需要先查找，则还是 O(n)。

### 3.2 数组扩容机制

- Java 数组创建后长度**不可变**。
- 所谓"动态数组"（如 `ArrayList`）底层就是数组，扩容时：创建一个新数组（默认约 1.5 倍），把旧元素 `System.arraycopy` 拷贝过去。
- 频繁扩容会有性能损耗，这是面试中"预估容量"（`new ArrayList<>(1000)`）的意义。

### 3.3 为什么 Java 中"数组是对象"

- `int[]`、`String[]` 等都是 `Object` 的子类，可以调用 `toString()`（但数组的 `toString()` 返回的是 `[I@哈希码`，需要用 `Arrays.toString()` 才能打印内容）。
- 数组对象在堆上分配，`arr` 变量存的是引用——这一点和链表的"引用连接"本质相同。

### 3.4 数组和链表如何配合

- **哈希表（HashMap）** = 数组（桶）+ 链表（冲突时挂链）+ 红黑树（冲突过多时链表转树）。
- **LinkedList** 是双向链表；**ArrayList** 是动态数组，两者是面试常对比对象。

### 3.5 常见误区提醒

1. `println(对象)` 输出的 `类名@哈希码` **不是内存地址**，是默认 `toString()` 的结果（哈希码通常由 `identityHashCode` 产生，与地址无必然关系）。
2. 数组 `toString()` 不会打印元素，必须用 `Arrays.toString()` / `Arrays.deepToString()`（多维）。
3. 链表"增删快"是**相对**数组而言，且特指拿到节点引用后改指针；单纯查找复杂度两者不同（数组 O(1)，链表 O(n)）。
4. 栈和队列（`Stack`、`ArrayDeque`、`LinkedList`）底层分别是数组/链表实现，`Stack` 类本身继承自 `Vector`（底层是数组），了解底层才能回答"为什么推荐用 `ArrayDeque` 而不是 `Stack`"。

---

> 💡 补充一句总结：**数组是"以空间换时间"（用连续内存换 O(1) 随机访问），链表是"以时间换空间"（用指针开销换 O(1) 插入删除）**。实际工程中两者常常组合使用（如 HashMap、Redis 的 ziplist + 链表），面试时能从"内存布局 + 复杂度 + 工程组合"三个维度回答，会很有说服力。
